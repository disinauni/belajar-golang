# Closures

Every function you've written so far has had a name and was declared at package level. But Go also allows **anonymous functions** — functions with no name that can be created right in the middle of your code, and even stored in a variable. When an anonymous function "remembers" a variable from the scope around it, that's called a **closure**.

## A Simple Anonymous Function and Closure

```go
package main

import "fmt"

func makeCounter() func() int {
    count := 0
    return func() int {
        count++
        return count
    }
}

func main() {
    counter := makeCounter()
    fmt.Println(counter())
    fmt.Println(counter())
    fmt.Println(counter())
}
```

Output:
```
1
2
3
```

## Breaking Down the Closure

**`func makeCounter() func() int`** — this is an ordinary function, but its return type is **another function**: `func() int` (a function with no parameters that returns `int`). A function that returns another function is called a *function factory*.

**`count := 0`** — a local variable inside `makeCounter`. Normally, a local variable "disappears" once its function finishes. But here, something special happens.

**`return func() int { count++; return count }`** — this anonymous function "closes over" the `count` variable from the scope around it. This is a **closure**: this anonymous function carries access to `count` along with it, even after `makeCounter` finishes executing and would normally "go out of scope."

**`counter := makeCounter()`** — `counter` now holds that anonymous function, complete with its own `count` that stays "alive" because the closure keeps hold of it.

**Every time `counter()` is called** — it increments `count` by 1 and returns its value. Because `count` belongs to this particular closure (it isn't re-copied on every call), its value **keeps growing** across calls: 1, 2, 3.

Think of a closure like a backpack an anonymous function carries wherever it goes — inside that backpack are variables from its "old home" (the scope where it was created), and it can keep opening and changing the contents of that backpack every time it's called.

:::note
If you call `makeCounter()` **again** to create `counter2 := makeCounter()`, `counter2` will have its **own** `count`, completely separate from the `count` belonging to `counter`. Every call to `makeCounter()` creates a brand-new `count` variable.
:::

## The Classic Gotcha: Closures Inside a Loop

This is one of Go's most notorious gotchas, and it's **especially important** to understand accurately for the specific Go version in use. Look at the following code:

```go
package main

import "fmt"

func main() {
    funcs := []func(){}

    for i := 0; i < 3; i++ {
        funcs = append(funcs, func() {
            fmt.Println(i)
        })
    }

    for _, f := range funcs {
        f()
    }
}
```

Output:
```
3
3
3
```

You'd probably expect the output to be `0 1 2` — but it's `3 3 3`! Why?

:::warning
**This is the behavior of older Go versions (including Go 1.13.5, which is what runs the code on this site).** The loop variable `i` in `for i := 0; i < 3; i++` is **shared** across all iterations — it is not re-copied on every pass. Every closure created inside the loop stores a **reference to that same `i` variable**, not a copy of its value at that moment. By the time the loop finishes, `i` holds the value `3` (the value that makes the condition `i < 3` fail) — and since every closure points to that same `i`, they all print `3` when called later.

As of Go 1.22, this behavior **changed**: the loop variable is automatically a fresh copy on every iteration, so the code above prints `0 1 2` on modern Go. But the playground on this site runs **Go 1.13.5** — before that change — so you still need to understand and apply the fixes below to get correct behavior here.
:::

### Fix 1: Shadowing — Make a New Copy Each Iteration

```go
package main

import "fmt"

func main() {
    funcs := []func(){}

    for i := 0; i < 3; i++ {
        i := i // shadow: declares a NEW variable named i, a copy of the loop's i
        funcs = append(funcs, func() {
            fmt.Println(i)
        })
    }

    for _, f := range funcs {
        f()
    }
}
```

Output:
```
0
1
2
```

**`i := i`** — this line looks strange but is very common in Go. The right-hand side (`i`) refers to the loop variable outside; the left-hand side **declares a new variable**, also named `i`, but living in the loop body's scope, and created **fresh on every iteration**. The closure created after this line captures this new `i` — whose value is "frozen" for that iteration — instead of the loop's shared `i` variable.

### Fix 2: Pass It as a Function Parameter

```go
package main

import "fmt"

func makeFunc(n int) func() {
    return func() {
        fmt.Println(n)
    }
}

func main() {
    funcs := []func(){}

    for i := 0; i < 3; i++ {
        funcs = append(funcs, makeFunc(i))
    }

    for _, f := range funcs {
        f()
    }
}
```

Output:
```
0
1
2
```

This fix relies on something you already learned: function parameters are **always copied (by value)**. Every call to `makeFunc(i)` copies the value of `i` **at that exact moment** into a fresh parameter `n` — and every call gets its own `n`, separate from every other call. The closure inside `makeFunc` captures `n` (which is already safe, per-call), not `i` (which the loop shares).

:::tip
Rule of thumb: if you create a closure inside a loop and that closure is **used later** (stored, sent to a goroutine, etc. — not called immediately in the same iteration), always be suspicious of the loop variable. Apply shadowing (`i := i`) or pass it as a function parameter to make sure every closure gets its own copy.
:::

## Common Mistakes

1. **A closure in a loop without shadowing, used later (the main gotcha above):**
   ```go
   for i := 0; i < 3; i++ {
       funcs = append(funcs, func() { fmt.Println(i) }) // all capture the same i
   }
   // Every closure prints the final value of i (3), not the value when it was created
   ```

2. **Assuming a closure copies a variable's value at the moment the closure is created:**
   ```go
   x := 10
   print := func() { fmt.Println(x) }
   x = 20
   print() // prints 20, NOT 10 — the closure captures the variable, not its value at that time
   ```
   A closure captures the **variable** (a reference), not the **value** at the moment the closure is created. This is different from an ordinary function parameter, which really is copied at call time.

## Summary

| Concept | Example |
|---|---|
| Anonymous function | `func() { fmt.Println("hello") }` |
| Closure | An anonymous function that captures a variable from the outer scope |
| Function factory | A function that returns another function, each call gets its own state |
| Closures capture variables, not values | Changing the variable afterward is still visible from the closure |
| Loop variable gotcha (Go 1.13.5) | Every closure in the loop shares 1 variable — the end result can be `3 3 3` |
| Shadowing fix | `i := i` inside the loop body |
| Function parameter fix | Pass `i` as an argument to another function |
