# Comparison & Logical Operators

A program that only computes without being able to "make decisions" is limited — our calculator from Unit 1 still feels rigid. Starting with this unit, you'll learn to build programs that react differently depending on the situation. First step: understanding the operators that produce `true`/`false`.

## Comparison Operators

```go
package main

import "fmt"

func main() {
    a := 10
    b := 7

    fmt.Println(a == b)  // false
    fmt.Println(a != b)  // true
    fmt.Println(a > b)   // true
    fmt.Println(a < b)   // false
    fmt.Println(a >= 10) // true
    fmt.Println(b <= 6)  // false
}
```

Output:
```
false
true
true
false
true
false
```

## Breaking Down the Comparison Operators

**`==`** — equal to. Notice the **two** equals signs — different from `=` (one sign), which is used for assignment.

**`!=`** — not equal to.

**`>` `<` `>=` `<=`** — greater than, less than, greater than or equal to, less than or equal to. All of these produce a `bool`.

:::tip
All of these operators work on `int`, `float64`, and `string` (string comparison in Go follows alphabetical/lexicographic order: `"apple" < "orange"` evaluates to `true`). They can't be used directly to compare slices, maps, or structs containing slices — that's a more advanced topic in later units.
:::

## Logical Operators

Sometimes one condition isn't enough — you need to combine several requirements at once.

```go
package main

import "fmt"

func main() {
    age := 17
    hasID := true

    canVote := age >= 17 && hasID
    fmt.Println(canVote) // true

    studentDiscount := age < 18 || age > 60
    fmt.Println(studentDiscount) // true

    noID := !hasID
    fmt.Println(noID) // false
}
```

Output:
```
true
true
false
```

## Breaking Down the Logical Operators

**`&&`** (AND) — the result is `true` only if **both** sides are `true`. `age >= 17 && hasID` evaluates to `true` because both requirements are satisfied.

**`||`** (OR) — the result is `true` if **either** side is `true`. `age < 18 || age > 60` evaluates to `true` because `age > 60` alone would be enough (though `age < 18` is also `true` here — wait, `17 < 18` is `true`! Try running it yourself and see).

**`!`** (NOT) — flips a bool value. `!hasID` flips `true` into `false`.

:::note
**Short-circuit evaluation** — Go does **not** evaluate the right side of `&&`/`||` if the result can already be determined from the left side alone. If the left side of `&&` is already `false`, the right side is **never executed** (because the AND result is guaranteed to be `false`). This is useful for code like `data != nil && data.Value > 0` — the second part is safe to run because Go already knows it won't check `data.Value` if `data` is actually `nil`.
:::

## Common Mistakes

1. **Using `=` (assignment) when you meant `==` (comparison):**
   ```go
   a := 5
   if a = 10 {  // ERROR: syntax error, non-boolean condition
       fmt.Println("this is an error!")
   }
   ```
   The good news: Go **refuses to compile** this mistake automatically, because `a = 10` is an assignment statement, not an expression that produces a `bool`. This differs from C/C++, which silently allow it (and it's often a source of bugs there).

2. **Comparing float64 with `==` for calculation results:**
   ```go
   result := 0.1 + 0.2
   fmt.Println(result == 0.3)  // false! (not a bug, it's floating-point precision)
   ```
   Decimal calculations have limited precision in nearly every programming language. To compare two float64 values as "approximately equal," you usually use a small tolerance (`math.Abs(a-b) < 0.0001`) instead of a direct `==`.

## Summary

| Operator | Function | Example |
|---|---|---|
| `==` `!=` | Equal to, not equal to | `a == b` |
| `<` `>` `<=` `>=` | Order comparison | `age >= 17` |
| `&&` | AND (both sides must be true) | `a && b` |
| `\|\|` | OR (either side true) | `a \|\| b` |
| `!` | NOT (flips the value) | `!valid` |

In the next lesson, we'll use these operators to make programs truly "make decisions" with **if-else**!
