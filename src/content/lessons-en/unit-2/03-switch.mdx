# Switch

You've already used `switch` briefly in the Unit 1 calculator project. Now it's time for a proper introduction — including one big difference from C++/Java that you need to know.

## Basic Syntax

```go
package main

import "fmt"

func main() {
    day := "Wednesday"

    switch day {
    case "Monday":
        fmt.Println("Start of the week")
    case "Wednesday":
        fmt.Println("Midweek")
    case "Friday":
        fmt.Println("Almost the weekend")
    default:
        fmt.Println("Just an ordinary day")
    }
}
```

Output:
```
Midweek
```

## Breaking Down Switch

**`switch day {`** — evaluates `day` once, then matches it against each `case`.

**`case "Wednesday":`** — if `day` equals `"Wednesday"`, run this block.

**`default:`** — runs when no `case` matches. It's optional (can be omitted).

## No Automatic Fallthrough!

This is the most important difference from C++/Java: in Go, **every `case` automatically stops after its block finishes** — it doesn't "fall through" to the next `case` like in other languages.

```go
package main

import "fmt"

func main() {
    value := 2

    switch value {
    case 1:
        fmt.Println("One")
    case 2:
        fmt.Println("Two")
    case 3:
        fmt.Println("Three")
    }
}
```

Output:
```
Two
```

The program **only** prints `"Two"` — it doesn't continue to print `"Three"`, even though no `break` was written. This is a big difference from C++, where you're **required** to write `break` at the end of every `case`, or execution will "fall through" to the next `case`.

:::note
If you actually **want** fallthrough behavior (rarely used, but occasionally useful), Go provides the explicit `fallthrough` keyword:
```go
switch value {
case 1:
    fmt.Println("One")
    fallthrough
case 2:
    fmt.Println("Two is also printed even though value isn't 2!")
}
```
Because it must be written explicitly, Go code is far less prone to the "forgot break" bug that's common in C/C++.
:::

## Switch Without an Expression

There's another very useful form: a `switch` with no value to match against, where every `case` holds its own boolean condition — this is a more concise alternative to a long chain of `if/else if`.

```go
package main

import "fmt"

func main() {
    score := 85

    switch {
    case score >= 90:
        fmt.Println("Grade: A")
    case score >= 80:
        fmt.Println("Grade: B")
    case score >= 70:
        fmt.Println("Grade: C")
    default:
        fmt.Println("Grade: D")
    }
}
```

Output:
```
Grade: B
```

**`switch {`** (no value after `switch`) — every `case` is treated as its own `if` condition, checked from top to bottom, stopping at the first one that's `true`. The result is identical to the `if-else if-else` pattern you wrote in the previous lesson, but it's more concise to read.

:::tip
Many Go programmers prefer a switch without an expression over a long chain of `if/else if` once there are more than 3-4 conditions — it's easier for the eye to scan.
:::

## Common Mistakes

1. **Thinking you need `break` at the end of every case:**
   ```go
   switch value {
   case 1:
       fmt.Println("One")
       break  // not wrong, but redundant — Go already stops automatically
   case 2:
       fmt.Println("Two")
   }
   ```
   It's not an error, but `break` here doesn't do anything that wasn't already happening automatically. Idiomatic Go code usually doesn't write `break` at the end of a case.

2. **Forgetting that cases are evaluated in order from the top, not all at once:**
   ```go
   switch {
   case score >= 70:
       fmt.Println("Pass")
   case score >= 90:
       fmt.Println("Excellent")  // NEVER reached for score >= 90!
   }
   ```
   Since `case score >= 70` already covers every score of 90 and above, the `case score >= 90` below it will never be reached. Ordering cases from most specific/strict to most lenient matters.

## Summary

| Concept | Example |
|---|---|
| Switch with a value | `switch day { case "Monday": ... }` |
| Switch without a value | `switch { case x >= 90: ... }` |
| Automatic stop | No `break` needed |
| Explicit fallthrough | `fallthrough` keyword |
