# If-Else

Here it is — the construct that lets a program truly "think." Our calculator actually already used `switch` (a similar concept) in the Unit 1 project. Now it's time to formally master `if-else`.

## Basic Syntax

```go
package main

import "fmt"

func main() {
    score := 85

    if score >= 90 {
        fmt.Println("Grade: A")
    } else if score >= 80 {
        fmt.Println("Grade: B")
    } else if score >= 70 {
        fmt.Println("Grade: C")
    } else {
        fmt.Println("Grade: D")
    }
}
```

Output:
```
Grade: B
```

## Breaking Down the If-Else Syntax

**`if score >= 90 {`** — notice there are **no parentheses** around the condition (unlike C++/Java, which write `if (score >= 90)`). But curly braces `{` are **mandatory**, even for a one-line body — Go doesn't allow `if condition print();` without `{}` at all.

**`else if score >= 80 {`** — checked only if the previous `if` condition was `false`. You can chain as many of these as you like.

**`else {`** — runs when all the conditions above it are `false`.

Go checks conditions **from top to bottom**, and stops at the first one that's `true` — the rest are skipped (exactly like `switch`, which you've already seen).

:::note
Why are curly braces mandatory? This is a deliberate Go design decision to avoid the classic "dangling else" bug from C — where forgetting to write `{}` can make a second line unintentionally fall outside the if block. By requiring `{}`, this kind of ambiguity simply cannot happen in Go.
:::

## If with an Init-Statement

This is a feature most other languages don't have: you can declare a variable **right before** the condition, on the same line.

```go
package main

import "fmt"

func divide(a, b int) (int, error) {
    if b == 0 {
        return 0, fmt.Errorf("cannot divide by zero")
    }
    return a / b, nil
}

func main() {
    if result, err := divide(10, 2); err == nil {
        fmt.Println("Result:", result)
    } else {
        fmt.Println("Error:", err)
    }
}
```

Output:
```
Result: 5
```

## Breaking Down the Init-Statement

**`if result, err := divide(10, 2); err == nil {`** — there are two parts separated by a semicolon: `result, err := divide(10, 2)` (the init-statement, run once before the check) and `err == nil` (the actual condition).

The big advantage of this pattern: the variables `result` and `err` **only live inside this if/else block** — once you leave the block, neither can be accessed anymore. This keeps scope tidy, without "leaking" temporary variables into the rest of the code.

:::tip
The pattern `if result, err := function(); err == nil { ... }` is very common in idiomatic Go code, especially for checking errors without cluttering the scope outside the if block. You'll see this pattern a lot once you learn error handling in Unit 6.
:::

## Common Mistakes

1. **Forgetting the curly braces:**
   ```go
   if score >= 90
       fmt.Println("A")  // ERROR: missing condition in if statement
   ```
   `{}` is mandatory, no exceptions, even for a single line.

2. **Trying to access an init-statement variable outside the block:**
   ```go
   if result, err := divide(10, 2); err == nil {
       fmt.Println(result)
   }
   fmt.Println(result)  // ERROR: undefined: result
   ```
   `result` and `err` only live for the duration of the related `if`/`else if`/`else` block — exactly like variable scope inside a function.

3. **Adding parentheses around the condition (not an error, but not idiomatic):**
   ```go
   if (score >= 90) {  // works, but gofmt/reviewers will ask you to remove it
       fmt.Println("A")
   }
   ```
   Technically this still compiles, but Go convention (enforced by the `gofmt` tool) is to omit the parentheses.

## Summary

| Concept | Example |
|---|---|
| Basic if | `if x > 0 { ... }` |
| Else if | `else if x < 0 { ... }` |
| Else | `else { ... }` |
| Init-statement | `if v, err := f(); err == nil { ... }` |
| Curly braces | **mandatory**, no parentheses around the condition |
