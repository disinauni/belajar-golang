# Range

Writing `for i := 0; i < len(data); i++ { data[i] }` every time you want to iterate over a collection gets repetitive and is prone to typos. Go has a more concise way: the `range` clause.

## Range on a Slice

```go
package main

import "fmt"

func main() {
    fruits := []string{"Apple", "Orange", "Mango"}

    for index, value := range fruits {
        fmt.Println(index, value)
    }
}
```

Output:
```
0 Apple
1 Orange
2 Mango
```

## Breaking Down Range on a Slice

**`for index, value := range fruits {`** — `range fruits` produces two values on every iteration: `index` (the position, starting at `0`) and `value` (the element at that position). This is far more concise than writing `fruits[i]` manually over and over.

**If you only need the value, not the index:**
```go
for _, value := range fruits {
    fmt.Println(value)
}
```
The underscore `_` (called the *blank identifier*) tells Go "I'm deliberately ignoring this value" — if you declare `index` but never use it, Go will error with "declared and not used," so `_` is the official way to discard a value you don't need.

**If you only need the index:**
```go
for index := range fruits {
    fmt.Println(index)
}
```

## Range on a String

This part needs extra attention:

```go
package main

import "fmt"

func main() {
    word := "Hello"

    for i, r := range word {
        fmt.Println(i, r, string(r))
    }
}
```

Output:
```
0 72 H
1 101 e
2 108 l
3 108 l
4 111 o
```

**`for i, r := range word {`** — for a string, `range` produces `i` (a **byte** position, not always neatly sequential 0,1,2,3 for non-ASCII characters) and `r`, which is of type `rune` (the Unicode code point for that character — that's why it prints as a number like `72` for `'H'`).

:::note
For strings containing non-ASCII characters (like "café" or emoji), the byte position from `range` can "jump" by more than 1 between iterations, because one Unicode character can use more than 1 byte. We'll cover this in more depth when we discuss `string`/`rune`/`byte` in Unit 5 — for now, just remember: **`range` on a string iterates per-character (rune), not per-byte**.
:::

## Range on a Map

```go
package main

import "fmt"

func main() {
    scores := map[string]int{"Budi": 88, "Ani": 92, "Citra": 75}

    for name, score := range scores {
        fmt.Println(name, ":", score)
    }
}
```

Output (the order may differ every time it runs!):
```
Ani : 92
Citra : 75
Budi : 88
```

**`for name, score := range scores {`** — for a map, `range` produces a `key` and a `value`. Notice the output above: **the order isn't guaranteed**! Go **deliberately randomizes** map iteration order every time it runs, so programmers don't accidentally come to rely on an order that was never actually promised.

:::tip
If you need to iterate a map in a consistent order (say, alphabetically by key), you need to collect all the keys into a slice first, sort that slice (`sort.Strings`), then iterate the sorted slice to access the map. We'll cover `sort` further in a later unit.
:::

## Common Mistakes

1. **Declaring the index but never using it:**
   ```go
   for index, value := range fruits {
       fmt.Println(value)  // ERROR: index declared and not used
   }
   ```
   Fix: replace `index` with `_` if you don't actually need it.

2. **Expecting consistent map ordering:**
   ```go
   data := map[string]int{"a": 1, "b": 2, "c": 3}
   for k := range data {
       fmt.Println(k)  // the order CAN differ each run!
   }
   ```
   Don't write logic that depends on a particular order when iterating a map — if you need order, sort the keys explicitly.

## Summary

| Target | Pattern | Result per iteration |
|---|---|---|
| Slice/Array | `for i, v := range s` | index, value |
| String | `for i, r := range s` | byte position, rune |
| Map | `for k, v := range m` | key, value (random order) |
| Ignore one | `for _, v := range s` | blank identifier `_` |
