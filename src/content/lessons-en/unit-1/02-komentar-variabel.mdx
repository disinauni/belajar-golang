# Comments & Variables

Imagine writing a recipe but forgetting to note down how much salt to use — a month later you're confused yourself. In programming, a similar problem happens all the time: you (or someone else) will forget **why** a line of code was written a certain way. The solution: **comments**. And to store data your program uses, we need **variables**.

## Comments

A comment is text the compiler ignores — purely for humans reading the code.

```go
package main

import "fmt"

func main() {
    // This is a single-line comment
    fmt.Println("Hello!") // can also go at the end of a line

    /*
       This is a multi-line comment.
       Great for longer explanations.
    */
    fmt.Println("Done!")
}
```

Output:
```
Hello!
Done!
```

## Breaking Down Comment Syntax

**`// single-line comment`** — all text after `//` until the end of the line is ignored by the compiler.

**`/* multi-line comment */`** — all text between `/*` and `*/` is ignored, and it can span multiple lines at once.

:::tip
A good comment explains **why**, not **what**. `// add 1` above `x++` is useless — what's more helpful is `// adjust the 0-based index to 1-based for display to the user`.
:::

## Variables

A variable is a named storage location for data. Go has two ways to declare one:

```go
package main

import "fmt"

func main() {
    var name string = "Alex"
    var age int = 17

    city := "Jakarta"

    fmt.Println(name, age, city)
}
```

Output:
```
Alex 17 Jakarta
```

## Breaking Down the Two Declaration Styles

**`var name string = "Alex"`** — the explicit way. The order is: the `var` keyword, the variable name, the data type, an equals sign, then the value. Can be used anywhere, including outside functions.

**`var age int = 17`** — the same pattern, using the `int` type for whole numbers.

**`city := "Jakarta"`** — *short variable declaration*. The data type is inferred automatically from the value (here, `string`, because `"Jakarta"` is wrapped in quotes). More concise, but it can **only be used inside a function** — not at the package/global level.

Think of `var` as filling out a full form (name, type, and value all written out), while `:=` is like filling out a quick form that automatically guesses part of the entry from what you wrote.

:::note
**Zero Value** — if you declare a variable without an initial value (`var total int`), Go does **not** leave it empty/undefined like many other languages. Go automatically fills in a *zero value*: `0` for numbers, `""` for strings, `false` for bools.
```go
var total int      // automatically 0
var message string // automatically "" (empty string)
fmt.Println(total, message)  // Output: 0
```
:::

:::tip
Go's naming convention for variables uses **camelCase** (`fullName`, not `full_name` or `FullName`) for ordinary variables. A capitalized first letter (`FullName`) has a special meaning — exported from the package — which we'll cover in Unit 8.
:::

## Common Mistakes

1. **Declaring a variable but never using it:**
   ```go
   func main() {
       name := "Alex"  // ERROR: declared and not used
       fmt.Println("Hello!")
   }
   ```
   Go **refuses to compile** if a local variable is declared but never used at all — unlike many other languages that only give a warning.

2. **Using `:=` outside a function:**
   ```go
   package main

   name := "Alex"  // ERROR: syntax error, non-declaration statement outside function body

   func main() {
       fmt.Println(name)
   }
   ```
   `:=` is only valid inside a function. At the package level (outside any function), you must use `var`.

3. **Redeclaring with `:=` in the same scope:**
   ```go
   name := "Alex"
   name := "Sam"  // ERROR: no new variables on left side of :=
   ```
   If the variable already exists in the same scope, use a plain equals sign (`name = "Sam"`), not `:=` again.

## Summary

| Concept | Example |
|---|---|
| Single-line comment | `// note` |
| Multi-line comment | `/* longer note */` |
| Explicit declaration | `var name string = "Alex"` |
| Short declaration | `name := "Alex"` |
| Zero value int/string/bool | `0` / `""` / `false` |
