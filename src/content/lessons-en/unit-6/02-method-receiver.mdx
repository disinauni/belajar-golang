# Method & Receiver

A struct that only stores data is useful, but a struct becomes far more useful once it has **behavior** — functions "attached" directly to it. In Go, functions like this are called **methods**, and the way you attach them is called a **receiver**.

## Declaring a Method

```go
package main

import "fmt"

type Square struct {
    Side float64
}

func (s Square) Area() float64 {
    return s.Side * s.Side
}

func main() {
    box := Square{Side: 4}
    fmt.Println(box.Area())
}
```

Output:
```
16
```

## Breaking Down the Method Syntax

**`func (s Square) Area() float64 { ... }`** — this is a method, not a regular function. There's exactly one difference: `(s Square)` sits between `func` and the method name. This part is called the **receiver** — it tells Go "this method is attached to the `Square` type".

Picture the receiver like a "belongs to" label on an item. `func Area(s Square) float64` (a regular function) and `func (s Square) Area() float64` (a method) essentially do the same thing — but a method can be called with `box.Area()`, far more natural than `Area(box)`.

**`s`** — the receiver name, freely chosen (convention favors short names, usually the type's first letter). Inside the method body, `s` acts like a regular parameter representing the struct instance that called it.

**`box.Area()`** — calls the method. Go automatically fills `s` with `box`.

## Value Receiver vs Pointer Receiver

This is the **most important** part of methods in Go: there are two kinds of receiver, and the difference is crucial.

```go
package main

import "fmt"

type Square struct {
    Side float64
}

// Value receiver -- operates on a COPY
func (s Square) ChangeSideWrong(newSide float64) {
    s.Side = newSide
}

// Pointer receiver -- operates on the ORIGINAL data
func (s *Square) ChangeSide(newSide float64) {
    s.Side = newSide
}

func main() {
    box := Square{Side: 4}

    box.ChangeSideWrong(10)
    fmt.Println(box.Side) // 4 -- unchanged!

    box.ChangeSide(10)
    fmt.Println(box.Side) // 10 -- changed!
}
```

Output:
```
4
10
```

## Breaking Down Value vs Pointer Receiver

**Value receiver `(s Square)`** — Go creates a **copy** of the struct when the method is called. Every change to `s` inside the method only happens to that copy, and it's gone as soon as the method finishes. Picture this like giving someone else a **photocopy** of your document — they can scribble on the photocopy all they want, your original stays clean.

**Pointer receiver `(s *Square)`** — Go hands over the **memory address** of the original struct, not a copy. Changes to `s` directly change the original data. This is like handing over the **actual house key**, not a photocopy — whoever holds that key can genuinely change what's inside the house.

**`box.ChangeSide(10)`** — notice, `box` isn't a pointer, yet this is still valid! Go automatically turns it into `(&box).ChangeSide(10)` behind the scenes, as long as `box` is a variable whose address can be taken (*addressable*).

:::tip
When should you use a pointer receiver? Whenever the method **needs to change** the struct's original data. When should you use a value receiver? When the method only **reads** data (like `Area()` above) and never changes it.
:::

:::warning
If one method of a type uses a pointer receiver, Go convention recommends **all** methods of that type use a pointer receiver too — even ones that only read data. This keeps things consistent and avoids confusion about which type you're actually holding.
:::

## Common Mistakes

1. **Using a value receiver when you need to change the original data:**
   ```go
   type Counter struct {
       Total int
   }

   func (c Counter) Add() { // logic ERROR: value receiver, not pointer
       c.Total++
   }

   func main() {
       c := Counter{}
       c.Add()
       c.Add()
       fmt.Println(c.Total) // 0 -- not 2, because Add() only changes a copy
   }
   ```
   This code compiles without error, but the result is logically wrong — a classic Go beginner trap.

2. **Calling a pointer receiver method on a value that isn't addressable:**
   ```go
   type Cat struct{ Age int }
   func (c *Cat) AddAge() { c.Age++ }

   func main() {
       cats := map[string]Cat{"Tom": {Age: 3}}
       cats["Tom"].AddAge() // ERROR: cannot call pointer method on cats["Tom"]
   }
   ```
   A value inside a map is **not addressable** — Go can't take its address, so a method with a pointer receiver can't be called on it directly.

## Summary

| Concept | Example |
|---|---|
| Method declaration | `func (s Square) Area() float64 { ... }` |
| Value receiver | `func (s Square) Method()` — operates on a copy |
| Pointer receiver | `func (s *Square) Method()` — operates on the original data |
| Call a method | `box.Area()` |
| Auto address | `box.ChangeSide(10)` equals `(&box).ChangeSide(10)` |
