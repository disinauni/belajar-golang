# Select & Buffered Channel

Di lesson sebelumnya kita belajar channel unbuffered yang selalu blocking sampai ada pasangan siap. Sekarang kita akan belajar dua alat tambahan: **buffered channel** (channel dengan "kotak penyimpanan" sehingga tidak selalu blocking) dan **select** (menunggu beberapa channel sekaligus, seperti `switch` tapi untuk channel).

Bayangkan buffered channel seperti **kotak pos** dengan slot terbatas: kamu bisa memasukkan surat tanpa menunggu tukang pos datang, selama slotnya belum penuh. Sementara `select` seperti resepsionis yang menjaga beberapa telepon sekaligus — begitu salah satu berdering, dia langsung mengangkatnya.

```go
package main

import "fmt"

func main() {
    ch := make(chan string, 2) // buffered channel, kapasitas 2

    ch <- "pesan 1" // tidak blocking, karena buffer masih ada slot
    ch <- "pesan 2" // tidak blocking, slot terakhir terisi

    close(ch) // tutup channel, tidak ada pengiriman lagi

    for pesan := range ch {
        fmt.Println("Terima:", pesan)
    }
}
```

Output:

```
Terima: pesan 1
Terima: pesan 2
```

## Membedah Konsep

### Buffered Channel: `make(chan T, kapasitas)`

```go
ch := make(chan string, 2)
```

Argumen kedua pada `make` menentukan **kapasitas buffer** channel. Buffered channel ini bisa menampung sampai 2 nilai **tanpa blocking**, meskipun belum ada goroutine lain yang siap menerima.

- Selama buffer **belum penuh**, `ch <- v` **tidak blocking** — langsung lanjut ke baris berikutnya.
- Kalau buffer **sudah penuh**, `ch <- v` akan **blocking** sampai ada slot kosong (misalnya karena ada goroutine lain yang menerima).
- Menerima dari buffered channel yang **kosong** tetap blocking, sama seperti unbuffered channel.

:::note
Channel unbuffered yang kita pelajari di lesson sebelumnya sebenarnya sama dengan buffered channel berkapasitas 0 — `make(chan int)` setara `make(chan int, 0)`.
:::

### Menutup Channel: `close(ch)`

```go
close(ch)
```

`close` menandai channel bahwa **tidak akan ada pengiriman lagi**. Setelah ditutup:
- Kamu masih bisa **menerima** semua nilai yang sudah ada di buffer.
- Mengirim ke channel yang sudah `close` akan **panic**.
- Menerima dari channel yang sudah `close` dan sudah kosong akan langsung mengembalikan **zero value**, bukan blocking.

### Mendeteksi Channel Closed: `v, ok := <-ch`

```go
v, ok := <-ch
if !ok {
    fmt.Println("Channel sudah ditutup dan kosong")
}
```

Bentuk penerimaan dua-nilai ini memberi tahu apakah nilai `v` benar-benar dikirim (`ok == true`) atau channel sudah closed dan kosong sehingga `v` cuma zero value (`ok == false`). Ini penting supaya kamu tidak salah mengira zero value sebagai data asli yang dikirim.

### `range` pada Channel

```go
for pesan := range ch {
    fmt.Println("Terima:", pesan)
}
```

Loop `range` pada channel otomatis menerima nilai satu per satu sampai channel **closed dan kosong**, lalu loop berhenti dengan sendirinya. Ini cara paling umum untuk membaca semua nilai dari channel tanpa perlu mengecek `ok` manual.

### `select`: Menunggu Beberapa Channel

```go
select {
case v1 := <-ch1:
    fmt.Println("Dari ch1:", v1)
case v2 := <-ch2:
    fmt.Println("Dari ch2:", v2)
default:
    fmt.Println("Tidak ada channel yang siap")
}
```

`select` menunggu **beberapa channel sekaligus**, lalu menjalankan `case` untuk channel yang **pertama siap**. Kalau beberapa channel siap bersamaan, Go memilih salah satu **secara acak** (bukan urutan penulisan). Blok `default` (opsional) langsung dijalankan kalau **tidak ada** channel yang siap sama sekali — membuat `select` jadi non-blocking.

:::tip
`select` tanpa `default` akan blocking sampai salah satu `case`-nya siap — mirip menunggu telepon mana pun yang berdering duluan. Dengan `default`, `select` langsung "menyerah" kalau semua channel masih sepi, cocok untuk polling non-blocking.
:::

## Kesalahan Umum

1. **Buffer penuh tapi mengira tidak akan blocking:**
   ```go
   ch := make(chan int, 2)
   ch <- 1
   ch <- 2
   ch <- 3 // BUG: blocking! Buffer kapasitas 2 sudah penuh, dan
   // tidak ada goroutine lain yang menerima.
   ```
   Buffered channel cuma menunda blocking sampai buffer penuh — bukan menghilangkan sifat blocking sama sekali.

2. **Mengirim ke channel yang sudah ditutup:**
   ```go
   ch := make(chan int, 1)
   close(ch)
   ch <- 5 // ERROR RUNTIME: panic: send on closed channel
   ```
   Setelah `close(ch)`, channel itu tidak boleh menerima pengiriman lagi — Go akan panic kalau dipaksa.

3. **Lupa bahwa menutup channel dua kali itu panic:**
   ```go
   ch := make(chan int)
   close(ch)
   close(ch) // ERROR RUNTIME: panic: close of closed channel
   ```
   Cukup `close` satu kali saja, biasanya dilakukan oleh goroutine **pengirim** (bukan penerima), setelah semua pengiriman selesai.

## Ringkasan

| Konsep | Contoh |
|---|---|
| Buffered channel | `make(chan int, 3)` |
| Kirim tanpa blocking (selama ada slot) | `ch <- v` |
| Tutup channel | `close(ch)` |
| Baca semua nilai sampai closed | `for v := range ch { ... }` |
| Deteksi channel closed | `v, ok := <-ch` |
| Tunggu banyak channel | `select { case ... case ... default: ... }` |

Sekarang kamu sudah bisa mengoordinasikan banyak channel sekaligus. Tapi bagaimana cara memastikan **semua** goroutine benar-benar selesai sebelum lanjut, dan bagaimana melindungi data yang diakses banyak goroutine bersamaan? Itu topik pelajaran berikutnya: **sync.WaitGroup dan Mutex**.
