# Struct Embedding

Go **tidak punya** konsep inheritance (pewarisan) seperti Java atau C++. Sebagai gantinya, Go punya **struct embedding** — cara menyisipkan satu struct ke struct lain sehingga field dan method-nya otomatis "ikut terbawa". Ini pendekatan Go untuk *code reuse*: komposisi, bukan pewarisan.

## Menyisipkan Struct

```go
package main

import "fmt"

type Hewan struct {
    Nama string
    Umur int
}

func (h Hewan) Deskripsi() string {
    return fmt.Sprintf("%s (%d tahun)", h.Nama, h.Umur)
}

type Anjing struct {
    Hewan
    Ras string
}

func main() {
    doggo := Anjing{
        Hewan: Hewan{Nama: "Rex", Umur: 3},
        Ras:   "Golden Retriever",
    }

    fmt.Println(doggo.Nama)
    fmt.Println(doggo.Deskripsi())
    fmt.Println(doggo.Ras)
}
```

Output:
```
Rex
Rex (3 tahun)
Golden Retriever
```

## Membedah Struct Embedding

**`type Anjing struct { Hewan; Ras string }`** — perhatikan `Hewan` ditulis **tanpa nama field**, cuma nama tipenya saja. Inilah yang disebut *embedded field*. Field ini otomatis diberi nama sama dengan nama tipenya, yaitu `Hewan`.

**`doggo.Nama`** — meskipun `Nama` didefinisikan di dalam `Hewan`, kamu bisa mengaksesnya langsung dari `doggo` tanpa menulis `doggo.Hewan.Nama`. Ini disebut **field promotion** — field dari struct yang di-embed "naik" ke struct luar.

**`doggo.Deskripsi()`** — hal yang sama juga berlaku untuk method: `Deskripsi()` didefinisikan untuk `Hewan`, tapi bisa dipanggil langsung dari `Anjing`. Ini **method promotion**.

Bayangkan `Anjing` seperti kotak yang di dalamnya ada kotak `Hewan` tanpa label. Karena tidak ada label, semua isi kotak `Hewan` terasa seperti "milik langsung" kotak `Anjing`.

**`doggo.Hewan.Nama`** — jalur lengkapnya tetap ada dan tetap valid. Kadang kamu perlu menulis ini secara eksplisit, misalnya kalau nama field-nya bentrok (lihat Kesalahan Umum).

## Bukan Inheritance — Ini Komposisi

Perbedaan penting: `Anjing` **tidak "menjadi"** `Hewan`. Kamu tidak bisa memperlakukan `Anjing` sebagai `Hewan` secara langsung seperti *upcasting* di bahasa berorientasi objek klasik. Yang terjadi adalah `Anjing` **memiliki** sebuah `Hewan` di dalamnya (relasi "has-a", bukan "is-a"), dan Go cuma mempermudah aksesnya lewat promotion.

Kamu juga bisa **override** method yang ter-promote dengan mendefinisikan method bernama sama langsung di struct luar:

```go
func (a Anjing) Deskripsi() string {
    return fmt.Sprintf("%s si %s", a.Nama, a.Ras)
}
```

Setelah ini, `doggo.Deskripsi()` memanggil versi milik `Anjing`, bukan lagi versi `Hewan`.

:::tip
Filosofi Go sering diringkas: *"prefer composition over inheritance"* (utamakan komposisi daripada pewarisan). Struct embedding adalah cara Go mendukung filosofi ini tanpa keyword khusus seperti `extends`.
:::

:::note
Embedding tidak terbatas pada struct — kamu juga bisa meng-embed interface ke dalam struct atau interface lain. Kita akan sedikit menyinggung ini di pelajaran berikutnya.
:::

## Kesalahan Umum

1. **Field ambigu kalau dua struct yang di-embed punya nama field sama:**
   ```go
   type A struct{ Nama string }
   type B struct{ Nama string }
   type C struct {
       A
       B
   }

   func main() {
       c := C{A{"X"}, B{"Y"}}
       fmt.Println(c.Nama) // ERROR: ambiguous selector c.Nama
   }
   ```
   Go tidak tahu `Nama` yang dimaksud milik `A` atau `B` — kamu harus tulis eksplisit `c.A.Nama` atau `c.B.Nama`.

2. **Lupa nama field embedded saat membuat struct literal:**
   ```go
   doggo := Anjing{Nama: "Rex"} // ERROR: unknown field 'Nama' in struct literal of type Anjing
   ```
   `Nama` bukan field langsung milik `Anjing` — kamu harus mengisinya lewat `Hewan`: `Anjing{Hewan: Hewan{Nama: "Rex"}}`.

## Ringkasan

| Konsep | Contoh |
|---|---|
| Embedded field | `type Anjing struct { Hewan; Ras string }` |
| Field promotion | `doggo.Nama` (padahal `Nama` milik `Hewan`) |
| Method promotion | `doggo.Deskripsi()` |
| Akses eksplisit | `doggo.Hewan.Nama` |
| Override method | Definisikan ulang method bernama sama di struct luar |

Di pelajaran berikutnya, kita masuk ke salah satu fitur paling khas Go: **interface** — tipe abstrak yang dipenuhi secara implisit, tanpa keyword `implements`.
